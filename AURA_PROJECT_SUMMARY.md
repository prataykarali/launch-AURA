# Project AURA - Comprehensive Technical Summary (v1.1)

This document provides a detailed overview of the current architecture, features, and optimizations implemented in Project AURA, excluding the classroom module.

---

## 1. Core Architecture (Flutter & Rust Integration)

The application utilizes a high-performance hybrid architecture, combining the **Flutter** UI framework with a custom **Rust** inference engine (**candle_LNN**) via `flutter_rust_bridge` (FRB).

### Components:
*   **AuraEngine (Rust)**: A localized LLM engine built using the `candle` framework. It supports GGUF model loading (LFM2.5-1.2B) and provides optimized CPU inference (NEON + dotprod SIMD).
*   **FFI Layer**: Managed by FRB, providing a seamless bridge for streaming chat responses, context injection, and state management.
*   **Window Management**: Utilizes `desktop_multi_window` and `window_manager` to support multiple independent UI contexts (Main Window and AURA Bar).

---

## 2. The AURA Bar (Working Implementation)

The AURA Bar is a specialized, persistent UI component designed to be a constant companion for the user, separate from the main dashboard.

### Features & Capabilities:
*   **Persistent Companion**: Designed to stay active even when the main application window is hidden or closed.
*   **Dynamic Visuals**: 
    *   **Waveform Visualization**: Real-time rendering of audio/state waveforms (`bar_waveform.dart`).
    *   **Particle System**: Interactive particle effects (`bar_particles.dart`) that react to AURA's state.
*   **State-Driven UI**: Reacts to various `BarState` values (idle, thinking, speaking, proactive) to change its appearance and behavior.
*   **Proactive Messaging**: Capable of displaying proactive messages to the user without direct interaction.
*   **Tray Integration**: Supports tray icon functionality for quick access and background persistence (`bar_tray_icon.dart`).
*   **Independent Windowing**: Fully decoupled lifecycle; has its own `BarWindowApp` and specialized overlay logic.

---

## 3. Advanced Window Lifecycle & Independence

We have implemented a robust multi-window system specifically optimized for Linux to ensure that closing one component doesn't kill the other.

### Key Logic:
*   **Independent Lifecycles**: The AURA Bar and Main Dashboard operate as separate window entities.
*   **Implicit View Protection**: On Linux, the first window (Main) is tied to the Flutter engine. We've implemented a `hide()` strategy:
    *   Closing the Main window hides it and removes it from the taskbar if the AURA Bar is still open, keeping the engine alive.
    *   **Cross-Window Communication**: Sub-windows (like the Bar) notify the Main engine when they close. The application only performs a full `exit(0)` when the **very last** visible window is closed.

---

## 4. High-Performance Inference & Streaming

Response latency has been optimized to achieve near-instant first-token delivery.

### Optimizations:
*   **Time To First Token (TTFT)**: 
    *   **Deferred Fact Extraction**: Background processing (learning facts from user input) is deferred until *after* the model starts replying.
    *   **History Re-routing**: Conversation history is moved from the `inject_cache` to the `per-turn prefill`, ensuring factual context remains stable and cached.
*   **Instant Streaming**: The pipeline renders tokens to the UI the moment they are generated by the model.
*   **Typewriter Dynamics**: Aggressive "catch-up" logic in Dart ensures the UI rendering stays in sync with the high-speed Rust token stream, eliminating visual stutter.

---

## 5. Intelligent Memory System (Smart RAG)

The memory system has been overhauled to provide relevant context without bloating the prompt.

### Features:
*   **Relevance-Filtered Injection**: Replaced "full note dumps" with a vector-search layer. Only the top 6 most relevant facts/notes are injected based on the current query.
*   **Fact Embeddings**: A dedicated SQLite-Vec table stores embeddings for all learned facts, enabling fast semantic retrieval.
*   **Automated Summarization Triggers**: 
    1.  **Session End**: Consolidates turns when the engine shuts down.
    2.  **Topic Shift**: Detects changes in conversation vibe/topic and summarizes previous context.
    3.  **Mechanical Cap**: Triggers a summary every 6 chat exchanges to keep the context window lean.

---

## 6. Dynamic Vibe & Response Control

The AI now adjusts its verbosity based on the "vibe" of the user's message.

### Mechanics:
*   **Vibe Analysis**: The embedder maps user input to 7 levels of verbosity (from ultra-short/concise to highly detailed/verbose).
*   **Multi-Loop Generation**: If a long response (e.g., 500 tokens) is requested but exceeds the single-turn cap, the engine automatically loops, re-injecting its own output to continue generating until the target length or a natural sentence completion is reached.
*   **Natural Stopping**: Stopping logic is tied to punctuation and sentence structure, preventing abrupt cut-offs.

## 7. Project Directory Structure (Core)

*   `aura_notebook/lib/`:
    *   `main.dart`: Standardized entry point with multi-window logic.
    *   `bar/`: Full implementation of the AURA Bar (UI, states, particles, waveform).
    *   `src/rust/`: Generated FRB bindings and Dart API wrappers.
    *   `screens/`: Main UI screens (Loading, Options, Notebook).
*   `candle_LNN/aura_lnn/src/`:
    *   `api.rs`: Public Rust API and thread orchestration.
    *   `engine/`: Core LLM logic, generation loops, and KV-cache management.
    *   `memory/`: Database store, vector search, and embedding logic.
